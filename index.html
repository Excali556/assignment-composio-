What stood out

82 of 99

Docs rarely say whether you can get access

Only 17 apps state a commercial access model on a page I could fetch. That, not API coverage, is what slows a toolkit rollout: the terms are missing, unstated or hidden behind JS. Filling the gap takes a pricing page or an email, and a person has to do it.

46 of 59

Token auth is the default wherever auth is documented

Of the 59 apps with documented auth, 46 use OAuth2 or some form of bearer, bot or access token. Static API keys turn up in 32 and HTTP Basic in 4, where Basic is usually just how the key travels (Freshdesk, Twilio, Discord).

11 live

MCP is real, but still rare

11 endpoints answered when I fetched them and named the app. 4 more are mentioned in docs with no URL I could resolve, and 84 had nothing. There is room to be first here, though "nothing found" is much weaker evidence than "nothing exists".

6 gated · 2 CLI-only

The hard blockers are commercial, not technical

Where access is stated, 10 apps are self-serve and 6 need a paid plan or partner sign-off. Two need a different build entirely: Sherlock and Mermaid CLI ship as CLIs with no HTTP API, so a toolkit there means wrapping the binary in a container.

The agent

Five stages, all runnable from the repo. The design point is simple: the model proposes and a deterministic binder decides what survives, so nothing gets asserted that the page does not say.

01

Fetch

For each app I try the curated doc URLs first, then guessed ones, over two transports (urllib, then curl), plus .md variants for Mintlify/Fern/Amazon-style docs.

Ran for real: 99/100 pages, saved verbatim to data/sources/<id>.txt with URL, status and timestamp.
02

Quality gate

Shells get rejected. The page has to name the app, contain both API and auth language, and not be an error page in its first 2.5k chars.

Ran for real: 1 pages rejected and listed at the bottom of this page.
03

Extract

The model reads the decision-relevant sentences and proposes fields with a short hint for each. It is allowed to say not stated.

Ran for real: 99 apps sent to groq:openai/gpt-oss-120b, groq:openai/gpt-oss-20b over an OpenAI-compatible endpoint by scripts/extract.py. The model returns fields plus a short hint phrase — never a quote.
04

Bind & verify

Each hint is located in the saved page and widened to the sentence around it, then checked as a verbatim substring. If that fails, the field drops to null.

Ran for real: 186/396 hints verified (53% rejected and dropped), 186 quotes published.
05

Second opinions

MCP links have to answer 2xx and name the app. Pricing pages get fetched where the docs are silent. A sample goes back to me for a manual re-read against the full text.

Ran for real: 17 MCP candidates checked, 11 confirmed; 25 apps audited (41 hits, 24 misses).

Where a human was needed

  • Picking entry URLs. Curated first, then /docs, /api and developer.* guesses, then .md/llms variants, then a text proxy. 21 apps needed a URL I found by hand (Amazon publishes llms.txt, Coda redirects to Superhuman Docs, FanBasis is now Commas), and 1 page still beats every transport.
  • Commercial access. Pricing pages are the only place self-serve vs gated is written down, and they are marketing pages: 13 of 23 attempts produced something usable, and almost none stated API access in words a quote could be bound to.
  • JS-rendered docs. 1 app defeated the fetcher outright. The honest answer there is no fetchable documentation in this run, not a guessed row.
  • The 24 audit corrections are mostly the model listing an auth variant my re-read did not, abstaining where the type was obvious, or reading a plan gate as silence.

What is still open

  • 1 of 100 apps are not researched. They are named at the bottom, not filled in. The first attempt's 100-row dataset was synthetic and now lives in discarded_synthetic/.
  • 82 of 99 access verdicts are undetermined and shown that way, not as self-serve.
  • MCP coverage is a floor. Nothing confirmed means the checks found nothing, not that nothing exists.

Limits, and what I would do with more time

What this page doesn't claim

  • That all 100 apps were researched. 99 were, at a standard where every field has a quote or says unknown.
  • That the access split is the true split. 82 of 99 verdicts are unknown, so the self-serve/gated ratio is a hint, not a census.
  • That MCP does not exist. Only that the checks I ran confirmed none.
  • That the model is right. It proposes; the binder and my audit decide what stays, and the audit found real classification errors (24 of 125 checks).

Next, in cost order

  • Cheap: a headless browser for the one page that beats every transport, and for the 18 apps whose saved text had no quotable fact (all JS shells).
  • Cheap: a second extraction pass over the 99 saved pages with a stronger model, aimed at the failure patterns in the audit. The corpus is already on disk, so it costs tokens only.
  • Medium: a pricing-page extractor with per-site selectors, to turn 82 undetermined access verdicts into facts.
  • Expensive, worth it: one email per gated app. That is the only way to learn approval timelines.
